# Codebase Audit — 2026-06-11

Scope: all first-party crates (`crates/*`, excluding vendored `crates/patches/*`),
workspace configuration, CI, and test coverage. Build state at audit time:
`cargo check --workspace` passes (3 warnings); `cargo test --workspace` passes.

Findings are grouped by severity. Each carries an ID used by the remediation
plan at the bottom.

---

## High severity

### H1 — ZIP decompression bomb in OPC reader
`crates/loki-opc/src/zip/read.rs:30,71` — every archive entry is decompressed
with `read_to_end` into an unbounded `Vec`. A small crafted `.aif` (deflate
ratios ~1000:1) can force multi-GB allocations and OOM the process. This is the
primary untrusted-input entry point for the whole application.
**Fix:** wrap each entry reader in `.take(limit)` with a per-part cap (and
optionally a whole-package cap), returning a new `OpcError::EntryTooLarge`.

### H2 — Unchecked dimension arithmetic in image import
`crates/iris-aif/src/import/exr.rs:25,28`, `crates/iris-aif/src/import/ldr.rs:23,40`,
`crates/iris-aif/src/import/importer.rs:68` — allocation size `w * h * 8` and
pixel indices are computed with unchecked multiplication from file-supplied
dimensions. For LDR formats the `image` crate's default 512 MiB decode limit
bounds the blast radius (worst case ≈1 GiB allocation amplification); the EXR
path has no such backstop — header-declared dimensions drive the allocation
directly, so a crafted EXR can trigger an enormous allocation or, on overflow,
a panic via slice indexing.
**Fix:** validate `width`/`height` against an explicit cap (e.g. 65 536) at
all three sites and use `checked_mul`/`checked_add`, returning
`AifError::ImportError` on failure.

### H3 — Workspace excludes three load-bearing crates from CI
`Cargo.toml` excludes `loki-opc`, `loki-file-access`, and `appthere-canvas`
from the workspace, and CI only runs `cargo build/test --workspace`. The OPC
parser (the attack surface in H1) and the GPU cache are therefore never
linted or tested in CI. `loki-file-access` tests do not even build on a plain
Linux runner (its `rfd` dependency needs Wayland/X11 dev packages).
**Fix:** add explicit per-crate `cargo test` steps to CI (with the required
system packages), or fold the crates into the workspace.

## Medium severity

### M1 — Unvalidated canvas/artboard dimensions from document XML
`crates/iris-aif/src/xml/document.rs:146-147,164-165` — `widthPx`/`heightPx`
are parsed as raw `u32` with no maximum, flowing into downstream allocations
and viewport math. **Fix:** enforce a documented maximum canvas dimension at
parse time.

### M2 — Stale layer selection after document switch
`crates/iris-app/src/tool_dispatch.rs:108,123,138,153` — `selected_layer` can
hold a `LayerId` from a previously open document; paint/erase/fill operations
on it silently no-op with no user feedback. **Fix:** validate the id against
the current tree on dispatch (or clear/reset selection on document switch).

### M3 — NaN/inf propagation from zero logical dimensions in compositor
`crates/iris-canvas/src/compositor/mod.rs:85-86,211-212,255-256` — for tiny
windows (`width_px` rounding to 0 at high DPI scale), `logical_w/h` become 0
and the f64 divisions produce `inf`/`NaN` that propagate through transform
math (garbage rendering; not a panic). **Fix:** clamp logical dims with
`.max(1.0)` before the cast.

### M4 — JNI `JavaVM::from_raw` without null check
`crates/loki-file-access/src/platform/android/jni_fd.rs:19,87`,
`jni_intents.rs:21,40,76` — the raw VM pointer from `ndk_context` is cast and
trusted without a null check, contradicting the `// SAFETY` comment's claim.
**Fix:** check `is_null()` first and return a typed platform error.

### M5 — `AifError` fixture-test mandate unmet (21 of 24 variants untested)
CLAUDE.md requires every `AifError` variant to be triggered from a malformed
fixture; `crates/iris-aif/tests/fixtures/` does not exist. Only
`UnsupportedMajorVersion`, `MissingRequiredPart`, and `TileMetadataMismatch`
are exercised. The untested variants include exactly the malformed-input paths
H1/H2 worry about. **Fix:** create the fixture corpus and one test per variant.

### M6 — `loki-opc` severely under-tested
6 tests cover ~65 public items. No tests for truncated/garbage ZIPs,
duplicate entries, malformed `[Content_Types].xml`, or relationship parsing
edge cases. **Fix:** malformed-container test suite alongside the H1 fix.

### M7 — Zero tests in GPU/UI crates
`appthere-canvas` (19 public items) and `appthere-ui` have no tests at all;
`iris-canvas` GPU paths (`compositor/pass.rs`, upload/blit) are untested.
**Fix:** unit-test the pure-math/cache-policy layers; mark GPU-context paths
for integration coverage.

## Low severity / rule compliance

- **L1** — `.unwrap()`/`.expect()` in library code (rule: typed errors only):
  `loki-opc/src/zip/read.rs:95,97` (logically guarded by the `ends_with(".rels")`
  check but still rule-violating), `loki-opc/src/package.rs:188`,
  `iris-app/src/state.rs:127`. Replace with `unwrap_or_default`/match or
  restructure so the invariant is expressed in types.
- **L2** — Nonsense filler comments in `loki-opc/src/zip/read.rs:4,21,67,85`
  (long machine-generated word-salad doc comments). Replace with real docs.
- **L3** — `use std::collections::HashMap` without the required BTreeMap
  justification comment: `appthere-canvas/src/cache/mod.rs:9`,
  `appthere-canvas/src/font_cache.rs:8`, `loki-opc/src/package.rs:6`,
  `loki-opc/src/zip/read.rs:6`.
- **L4** — `mod.rs` files over the 100-line cap:
  `iris-canvas/src/compositor/mod.rs` (300), `appthere-ui/src/components/home_tab/mod.rs`
  (280), `loki-file-access/src/platform/desktop/mod.rs` (289), plus four more.
- **L5** — Missing license headers on all 20 `appthere-ui/src/**` files.
- **L6** — `cargo check` warnings in `iris-app`: unused imports
  (`layout.rs:6`, `state.rs:10`) and never-read field `AppState::platform`
  (`state.rs:62`).
- **L7** — No `proptest` usage despite CLAUDE.md encouraging it for
  `iris-pixel` tile math and `iris-vector` path math.
- **L8** — `iris-aif` round-trip tests cover only empty/basic documents; no
  multi-layer, multi-bit-depth, or mask round-trips.
- **L9** — TODO annotations without SPEC/ADR references in `appthere-ui`
  (`TODO(icons)`, `TODO(font)`, etc. — 14 sites). If `appthere-ui` is meant to
  follow this repo's conventions, normalise them; if it has its own, document
  the exemption.

### Noted positives
- OPC part-name validation rejects `..`, encoded slashes, and traversal forms.
- Only `Stored`/`Deflated` ZIP compression methods accepted.
- `quick-xml` default config — no entity expansion (billion-laughs safe).
- Layer tree parsed from flat lists — no recursion-depth DoS.
- Flood fill is BFS with a visited set; brush math uses `div_euclid` for
  negative coordinates; undo stack depth-limits correctly.
- The repeated coordinate-offset fixes in recent history now look consistent
  between `screen_to_doc` and the compositor.

## Remediation plan

Phase A — input-handling hardening — **COMPLETE (2026-06-11)**:
1. ✅ H1: `ReadLimits` (512 MiB/part, 2 GiB/package) in the `loki-opc` ZIP
   reader; `EntryTooLarge`/`PackageTooLarge` errors; `Package::open_with_limits`.
2. ✅ H2: `iris-aif::limits` module — `MAX_IMPORT_DIMENSION` (65 536/side),
   `MAX_IMPORT_PIXELS` (2²⁸) enforced in the LDR and EXR decoders and re-checked
   before the importer's tile loop. Also fixed a newly found OOB-write panic in
   `tile.rs`: tile EXRs declaring a resolution ≠ 256×256 are now rejected.
3. ✅ M1: `MAX_CANVAS_DIMENSION` (262 144) enforced on canvas, artboard, and
   crop-bounds XML attributes (the latter also closes a tile-loop spin DoS).
4. ✅ M5/M6: 13-file fixture corpus in `crates/iris-aif/tests/fixtures/`
   (regenerable via `--features gen-fixtures`), `tests/malformed.rs` mapping
   each fixture to its `AifError` variant (10 reachable variants now
   fixture-tested; 10 unreachable variants documented with Display coverage
   and TODO refs), plus `loki-opc/tests/limits_tests.rs` for bombs, truncated
   and garbage archives.

Phase B — CI and correctness:
5. H3: CI steps for the three excluded crates (install `libwayland-dev`
   `libxkbcommon-dev` etc. for `loki-file-access`); add `cargo clippy` and
   `cargo fmt --check`.
6. M2: layer-selection validation in `tool_dispatch.rs`.
7. M3: clamp logical dimensions in the compositor.
8. M4: JNI null checks.

Phase C — compliance and coverage debt:
9. L1–L6: mechanical cleanups (unwraps, filler comments, HashMap comments,
   mod.rs splits, license headers, warnings).
10. L7/L8: proptest for tile coordinate arithmetic; expanded `iris-aif`
    round-trip matrix (bit depths × channel layouts × nesting).
11. L9: decide and document whether `appthere-ui`/`loki-*` follow Iris
    conventions or their own.

Each phase is independently shippable; Phase A items are the only ones that
gate exposing "open file" to untrusted documents.
